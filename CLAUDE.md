# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

xilo — self-hosted Nix binary cache in a single Go binary (server + client CLI in one, `cmd/xilo`). SQLite (or PostgreSQL) for metadata, local-disk or S3 for chunk bytes, FastCDC content-addressed dedup, multi-tenant admin dashboard.

## Commands

Everything goes through `just` (run `just` to list recipes):

- `just build` — css + templ generate + `go build` into `./bin/xilo`
- `just test` — css + generate + `go test ./...`
- `just lint` — css + generate + golangci-lint + `goimports -w .` + `go vet ./...` + a `-tags noserver` build. **It rewrites your files.** `.golangci.yml` is a stdlib-first set (`modernize`, `usestdlibvars`, `perfsprint`, `mirror`, `intrange`, `exptostd`, `errorlint`, `staticcheck`, …) run with `--fix`: anything auto-fixable is applied, never reported, so a finding that survives is one no fixer can write. CI runs the same set read-only — commit what `just lint` changed.
- `just check` — everything CI runs (lint, test, schema-check, nix-check)
- `just release-patch` / `-minor` / `-major` — gate on the default branch, resync schema/lock/vendorHash, tag and push; the tag push publishes the release (RELEASING.md). `just release-preview` is the dry run.
- `just dev` — UI dev server (`scripts/dev.sh`): seeds a throwaway instance under `tmp/dev` with dummy data, then runs `air` on :8090 so every `.go`/`.templ`/`.css` save rebuilds and restarts; under `XILO_DEV` the page morphs itself in place (idiomorph) instead of reloading. Sign in admin / demo.
- Single test: `go test ./internal/server/ -run TestName` — but run `just generate` (templ) first if any `.templ` changed, and `just css` if classes changed.

Generated artifacts are **regenerated, never hand-edited, and mostly git-ignored**:

- `internal/server/views/*_templ.go` — from `.templ` via `templ generate` (never committed)
- `internal/server/static/xilo-tw.css` — Tailwind v4 build via `just css` (scripts/build-css.sh; scans `views/*.templ`, `views/icon.go`, and the templui module)
- `schemas/xilo.schema.json` — `just sync-schema` after changing `config.Config`. Generated by `tools/schemagen`, deliberately *not* a `xilo` subcommand: `invopop/jsonschema` drags `go/parser` and a second YAML library into whatever links it (~1 MB of binary) for something only CI and `just` ever run.
- `flake.nix` vendorHash — `just sync-vendor-hash` after any dep change (`just update` does deps + hash together; never edit hashes by hand). One hash covers every package because `proxyVendor = true` hashes the module cache; do not switch to vendor mode, whose contents depend on the generated `_templ.go` and on build tags.

## Architecture

Request path: `cmd/xilo` → `internal/server` (one `http.ServeMux`, routes registered in `admin.go`/`register.go`/`api.go`/`cache.go`) → `internal/store` (DB) + `internal/storage` (chunk bytes).

- **`internal/store`** — all writes funnel through a single writer goroutine (`db.go`), so SQLITE_BUSY cannot happen; never open a second write path. `pgdriver.go` adapts the same queries to PostgreSQL.
- **`internal/storage`** — named backends (local/S3), assignable per cache. Chunk bytes never touch the DB.
- **`internal/server`** — three surfaces: the Nix binary-cache protocol (`/c/{account}/{cache}/…`, `cache.go`, fails closed on missing data), a token-authed JSON API (`/api/v1/…`, `api.go`/`adminapi.go`), and the session-authed admin UI (`/admin/…`).
- **`internal/push`** — the push client's fast paths, all optimistic: cached chunk manifests (`state.go`, keyed by store hash + NAR hash + chunking params), the server's bloom presence filter (`internal/bloom`, served by `internal/server/chunkfilter.go`), and pipelined negotiation windows. Their single safety net is `put-path`: it re-stamps then re-checks every chunk and answers **409 + the missing hashes**, which makes the client redo that path with all shortcuts off. Never weaken that check, never make a shortcut skip the 409 fallback, and never let a manifest be keyed by store path alone (input-addressed paths can be rebuilt with different bytes).
- **`internal/nar`** — writes the Nix Archive format, byte-for-byte as `nix-store --dump` does (validated against real nix in `nar_test.go`). The push client serializes locally instead of spawning a subprocess per path; every dump is checked against the NarHash nix recorded, and a mismatch re-dumps with `nix-store --dump` (also forced by `XILO_EXTERNAL_DUMP=1`). Never change the byte layout without the differential test passing — a wrong archive means a wrong NarHash for everything pushed.
- **`internal/cli`** — the client subcommands (push/pull/login/cache/fsck) speaking to the JSON API. `serve.go` is the *only* file here allowed to import `internal/server`: it is behind `//go:build !noserver`, with a stub in `serve_noserver.go`, so the `noserver` tag drops the server (and the templ/Tailwind build) from the graph. That tag is what makes `packages.xilo-cli` buildable where nixpkgs has no `tailwindcss_4` (riscv64-linux). Any new server import outside `serve.go` breaks it — `just lint` and CI both compile the tag to catch that.
- **`internal/billing` is a seam, not an integration.** `Provider` has three calls (checkout, read a subscription, cancel) and `billing.Disabled` — the default on `Server.billing` — answers `ErrDisabled` to all of them, because a checkout that silently does nothing is worse than one that says billing is not configured. Nothing outside that package imports a payment SDK, so "does this instance charge" stays one wiring decision. Plans carry `PriceCents` (whole units in the form, cents in the row — rounding a price twice is how an invoice stops matching the page that sold it), `Interval`, and `ExternalID` (the provider's price handle, so neither side invents the join); accounts carry `subscription_id`. A priced catalogue does not require a connected provider: publishing prices and taking money are separate steps.
- **Accounts have a lifecycle**, because a tenancy that stops paying is not a tenancy to delete: `StatusActive` → `StatusPastDue` (still serves, takes nothing new — a missed payment must not break someone's build mid-afternoon) → `StatusSuspended` (serves nothing), and `deleted` remains the end of the line that only `DeleteOrg` writes. Enforced in two places and no others: `Server.cache()`, the resolver *every* binary-cache handler goes through, refuses a suspended account, and `requirePush` answers 402 for past-due — put a new cache handler in and it inherits the rule. The sysadmin's levers live on the console's workspace rows.
- **Instance rules** (`rules.go`) are the sysadmin's ceilings and defaults, stored in `settings` and read *at the point they apply* rather than at boot, so changing one needs no restart: the storage ceiling (`instanceCap`, overriding `limits.total` when set), the retention a new cache inherits, the longest a token may live (`capTokenExpiry` — applied on create *and* edit, and it caps "never" too), and the plan a signup lands on. Every rule has exactly one enforcement site and an empty field means no rule, which is what a hobbyist's instance looks like; a rule the UI can set but nothing consults is worse than no rule. They are registered outside `registerTenancy` on purpose — ceilings are not part of the self-service surface.
- **Two jobs, two vocabularies.** `users.role` is the *instance* role — `store.RoleSuperadmin` runs the service (policy, plans, storage, every organization) and owns nothing in it; ask `u.Superadmin()`, never compare the string, because `account_members.role` says "owner" too and means something else entirely (authority *inside* one organization). A superadmin gets no account of its own (`CreateUser`), so on a single-tenant instance boot also creates a workspace named after them and makes them its owner — one person wearing both hats is the hobbyist shape, and it is the only place the two roles blur. The sidebar splits on this: an **Instance** group (Console, Settings, Status, Activities) for superadmins, a **Workspace** group for whoever is actually in an organization. `/admin/console` is the instance overview; `/admin` is one account's.
- **Sessions are a wallet** (`wallet.go`): one browser may hold several signed-in users at once and switch between them from the sidebar footer, so a second account never costs you the first. The `xilo_accounts` cookie carries the session ids, which makes it N session cookies in one — it wears the same flags, and nothing in there grants a session, it only re-selects one already authenticated. The account menu posts a **user id**, never a session id: the ids are the secret, and a page that renders them puts them in caches, history and screenshots. Signing out drops that account only and lands on the next one held. Any new path that mints a session must call `addToWallet` (and `reissueSession` when replacing the current one), or the browser forgets it is signed in as that person.
- **Every account is an organization** — a workspace, in the UI's words. Caches belong to one, tokens scope to one, a plan and its usage attach to one, and a membership is the only way to reach any of it; a single person's workspace is an organization with one member, named after them. `accounts.kind` is provenance, not permission: nothing branches on it, and "is this a user's own workspace" is `slug == username`. Two rules keep that honest — a live user's own workspace cannot be deleted on its own (`ErrOwnWorkspace`; it goes with them, so every user always has somewhere to put a cache), and the username of any user that ever existed is reserved forever (`ErrSlugReserved`), because `DeleteUser` leaves that workspace's caches in place and adopting the slug would re-parent them to whoever took the name. `OwnsOrgs` excludes the user's own workspace or no user would be deletable.
- Multi-tenancy: `config.SelfService` gates registration, plans, quotas, user workspace-creation. Caches live at `account/cache`. Organizations have one home — `/admin/orgs` (`orgs.templ`), listed in the sidebar for anyone in one or able to create one — never a card on the account page and a second list in instance settings. The admin is always inside **exactly one account**: `activeContext` resolves the context cookie to an account the user may act in and falls back to `defaultContext` (their own, or the first with caches in it) — there is no "all accounts" view, because a figure that silently covers one account or five depending on a setting elsewhere answers nothing. The switcher is a workspace picker, so it lives in the sidebar footer beside the identity it acts as, not above the navigation as a filter.

## Admin UI conventions (internal/server/views)

- **templUI components only** (`github.com/templui/templui/components/*`, pinned version in go.mod). Native HTML is allowed only where no component exists: `<form>`, hidden inputs, `<a>` links, `<img>`, `<pre>/<code>`, headings, layout divs. Icons via the templui `icon` package through the `Icon`/`IconClass` helpers (`icon.go`) — never raw SVG or another icon lib.
- **All user-visible text goes through `T(ctx, "key")`** against the catalogs in `i18n.go` (+ `i18n_de|fr|es|zh|ja.go`) — including placeholders, aria-labels, tooltips, confirm messages, server-side flash messages (`views.T(r.Context(), …)` from handlers), transactional email, and the plan-quota errors that also surface in the CLI. No hardcoded UI strings. Delete keys when their last use goes.
  - A message with a value in it is **one format string** used via `Tf(ctx, "key", args…)` — never a translated fragment concatenated with a name, which only reads correctly in English. Translations may reorder with `%[2]s`.
  - Locale comes from the context: middleware (`server.go`) resolves `users.locale`, else `Accept-Language`, and stores it with `views.WithLocale`. Email renders in the **recipient's** locale (`mailCtx`), not the sender's. Adding a language = one catalog map + a `Locales` entry; missing keys fall back to English per key.
  - Three tests hold the line: `TestCatalogCoversEveryLookup` (every literal key exists, and `T`/`Tf` matches whether the value takes arguments), `TestCatalogsAgreeOnArguments` (every translation consumes the same args), and the smoke test's English markers.
  - **Write for the slot, not for a screenshot.** A string may assume everything the surrounding UI already says: an option under a *Language* label is "Auto", not "Follow my browser"; a submit inside a dialog titled *New token* is "Create"; a confirm under *Delete cache?* is "Delete"; an empty state inside the *Plans* card is "None yet."; a search box with a magnifier is "Search". Shared keys exist for exactly this — `action.new/create/add/save/delete/remove/reset`, `empty.none`, `empty.nomatch` — reuse them instead of minting `plan.create`, `caches.nomatch` and friends. Full sentences are for the places with no context to lean on: flashes, confirm bodies, email, and validation rules.
  - Errors the user cannot act on never reach the page: `uiFail`/`uiError`/`flashErr` log the Go error and show a translated sentence; `flashStore` maps the `internal/store` sentinels (`ErrOwnerLocked`, `ErrPlanInUse`, …) to catalog keys. API and binary-cache surfaces keep their English wire text — do not translate those.
- **Tooltips**: the `WithTooltip(text)` partial (partials.templ), never `title=` attributes. Keep `aria-label` on icon-only buttons. Their *look* is not set at the call site — `css/input.css` styles every hover-triggered popover (`[data-tui-popover-root]:has(> [data-tui-popover-type="hover"]) > [data-tui-popover-content]`), which is the only way `WithTooltip` and templui's own sidebar-rail tooltip can stay identical. Flat, 16rem, `pointer-events`/`user-select: none`, no arrow, 200/100ms delays. Keep the text to a few words; the long ones are data (store paths, user agents) and wrap.
- Shared partials in `partials.templ`/`forms.templ` — reuse them; don't hand-roll equivalents. Page chrome: `Crumbs` (trail above deep pages), `PageHeader` (title + prose subtitle + actions slot), `PageHeaderCode` (same, but the subtitle is a machine string — a cache URL, a store path — so it sets in mono), `SectionHeader` (title + actions slot), `CardHeaderRow` (card title + action). Sections and lists: `ListSection(title, actions)` (heading row + rows — every titled list is one), `TableCard` (a table ruled off the page with `border-y`, wide ones scroll inside it and never push the page), `ListBox` (bordered box, only for a list nested inside a card, e.g. the chunk accordion) — never a hand-written `overflow-hidden rounded-lg border` div around a table. Panels: `SettingsCard(title, hint)` for anything you submit or copy; don't spell out `card.Header`/`card.Title`/`card.Content` by hand. Readouts: `StatRow` + `StatTile` (the strip a page opens with), `Readout` (value and label on one line), `DedupBar` (logical vs physical with the ratio — the dashboard's and the cache page's one loud element), `StoreHash` (a store or chunk hash, leading characters at contrast and the tail dimmed). Rows: `RowActions` (the right-aligned action cluster), `Meta` (the mono quantity riding beside a name), `SettingRow` (a setting's name, its current value in mono, and the control that changes it — the account page is a list of these, and the forms live in the dialogs they open). Controls: `PlusButton` (create trigger), `RowAction` (icon-only row button, size-8, tooltip + aria-label), `ActionRow` (sentence + button, wraps), `DialogBox` + `DialogFooter` (every form dialog: title, hint, form, cancel + submit), `ConfirmForm`, `SearchInput`, `EmptyState`, `PagerNav`, `SortHead`, `WithTooltip`. Status and role are glyphs, not pills: `StatusIcon` (token active/expired/revoked) and `RoleIcon` (superadmin/owner/admin/user/pending) carry the word in a tooltip + aria-label. Forms: `Field`, `FieldInfo` (explanation as an info glyph on the label, never a hint line under the control), `ExpiryField`, `PermSwitchID`, `DurationInput`, `SizeInput`.
- **Machine truth is monospace, prose is sans.** Hashes, byte sizes, counts, ratios, durations, timestamps, status codes, store paths, cache refs: `font-mono` + `tabular-nums`, because they are read in columns and compared. Titles, labels, hints and sentences stay sans. This is what makes the admin read as an instrument over a content-addressed store rather than a generic dashboard, so do not set a quantity in sans "because it looks calmer".
- **An empty list hides its own controls.** No rows and no query means no search box and no create button in the section header: the empty state (or, on the dashboard, the onboarding block) carries the single call to action. A list that came back empty *from a filter* keeps them — the search box is how you get out of that. Two consequences: the empty state has to render the whole create dialog, not just a `dialog.Trigger`, because the header's copy is not on the page; and `sectionAction(show, …)` is how a `ListSection` drops its header control. The dashboard goes further on first run (`firstRun`/`noTokensYet` in data.go) — no cache yet means the token section is not rendered at all, since there is nothing to scope a token to.
- Empty states come in two sizes: `EmptyState` (icon, rules, padding) frames a section of the page; `EmptyLine` is one muted line for a list already inside a card, which does not need a second frame around "None yet.".
- `DedupBar` renders nothing when nothing is stored — "1.00×" over a bar that is entirely "saved" claims a win for an empty cache.
- **Cards enclose, rules separate.** A card is for an object you act on as a whole — a form you submit, a snippet you copy (`SettingsCard`). A list of things is a section on the page ground: `ListSection` + `TableCard`, hairline rules, no card wall. Stacking every region in an identical rounded box is the look this UI was deliberately moved away from.
- Meta lines join their clauses with `views.MetaSep` (an em space), never `" · "`. A row of middle dots reads as one long sentence instead of three separate facts, and it is one of the tells of generated UI.
- Search fields never show the browser's own clear button: `searchClearLayer` (layout.templ) decorates every `input[type=search]` on the page — ours and templui's combobox search alike — with a cloned templui ghost button, and `input.css` hides the native one and reveals ours via `:placeholder-shown`. Nothing to do at the call site; a new search box gets it for free. `SearchInput` sizes a box of its own around the field, because templui wraps every input in a hard-coded `relative w-full` div — size the input alone and the wrapper still spans the row, pinning the field to the section title instead of its create button.
- A selectbox gets its search field only past `searchThreshold` options (`noSearch(n)`, helpers.go) — four or fewer are faster to point at than to type into, and the box costs a row of the popover and a focus stop. Every `selectbox.Content` passes `NoSearch`. Its chevron is never traded away either: templui swaps the chevron for a clear-x once a value is picked, and since `input.css` hides that x (every select here is a required choice), a filled select would otherwise read as a text box — so the chevron is pinned visible in the same place.
- A searchable selectbox is a combobox, and `comboboxKeysLayer` (layout.templ) makes it behave like one: focus never leaves the search field, the arrows move a separate active option (`data-tui-active` + `aria-activedescendant`), Enter picks it (or the first match), Escape closes the one open list and hands focus back to the trigger. templui's own model moves DOM focus onto the options, which is why typing stopped working after the first ArrowDown. The handler runs in the capture phase and stops propagation only for the keys it takes over.
- No hardcoded English anywhere a user can read it: handlers use `views.T(r.Context(), …)` for every flash and inline message (login/register errors included); tab labels and chip labels go through `T` too. Accordions (`<details>`) are for optional bulk only (chunk lists); settings live in plain cards.
- Control heights are a rule, not a choice: header/toolbar rows are h-8 (`SizeSm` buttons, `SearchInput`), form controls h-9 (default `input`/`button`), row actions size-8, chips h-7. Never mix h-8 and h-9 in one row.
- Layout grids are `grid gap-6` for cards (`items-start`, so a short panel beside a tall one does not stretch) and `StatRow` for readouts — never a hand-written KPI grid. `StatRow` is a wrapping row of fixed-width tiles, not a grid of equal fractions: three readouts in a grid spread themselves across the full width and stop reading as a group, and the strip has to look the same on a page with three of them as on one with twelve. A section header keeps its controls on one line — if they collide with the heading on a phone, shorten the heading rather than letting the row wrap. `.grid > *` has `min-width: 0` globally (input.css) so long `<pre>`/tables shrink instead of widening the page. Sortable tables are `table-fixed` with sized meta columns and rely on `TableCard`'s min-width floor. An actions slot that can hold a `SearchInput` must be able to grow (`flex-1`): a `w-full` field inside a content-sized flex item resolves to zero width, which is how search once became unreachable on phones.
- Colors are tokens only: `text-success`/`text-warning`/`text-destructive` and the shadcn set, never `text-green-500`-style palette classes. Palettes (per user, `users.theme`, `views.Palettes` in `theme.go`) are variable blocks in `css/input.css` keyed on `html[data-palette=…]` with a `.dark` half each; adding one means both halves plus a `Palettes` entry.
- **Primary is rationed, and it means one thing: this submits the form you are in.** `--primary` marks the bytes deduplication saved (`DedupBar`) and a form's own Save/Create/Update — on the page ground or in a dialog. Everything that *opens* something (a dialog, an enrolment page, a browser prompt) is an outline `SizeSm` trigger, however much it looks like the next step: `PlusButton`, `disabledCreate`, a `ConfirmForm` trigger, the 2FA Enable button. A settings panel with no fields to fill in has no Save at all — its switches submit on change (`policySection`, the account page's appearance card), which is also why it is a ruled section and not a card. Openers are outline (`PlusButton`), filter and segment selections are `VariantSecondary`/`VariantGhost` — which state a filter is in is not an action. Accent *text* uses the `text-brand` utility, not bare `text-primary`: every palette picks `--primary` as a fill with `--primary-foreground` on top, so raw it fails as text on whichever theme it was not chosen for (xilo's amber is oklch(85%) — invisible on white). `text-brand` mixes it toward the foreground, which is correct in both directions for every palette.
- Code boxes (`snippetBlock`, `CopyField`, `SecretCard`) hide their scrollbar (`scrollbar-none`) and every copy button confirms with the shared toast (`copyToastScript` in layout.templ).
- Per-row dialogs must prefix every input/switch DOM id with the dialog id (see `planFormBody`/`tokenFormBody`) — fixed ids duplicate across rows.
- House style: create-triggers are `PlusButton`; row actions are `RowAction` (or `ConfirmForm` with `IconOnly`) inside `RowActions`; confirm dialogs set `Danger` for irreversible actions; tables of sortable data use `table-fixed` + explicit column widths + `SortHead` inside `TableCard`; a list nested inside a card uses `ListBox`, not another card; badge text is lowercase.
- One loud element per page, and it is the thing the page exists to answer: the dedup bar on the dashboard and the cache page, the health word on status. Everything around it stays at one quiet weight.
- **Charts** (status page, templui's Chart.js wrapper): one series per chart, so no legend and **no area fill** — a 2px line over a recessive horizontal grid, with the title and the current value as the direct labels. Line colors are the four fixed categorical slots in `statusChartMeta`, literal hex (canvas resolves neither `var()` nor `color-mix`), validated against both surfaces — never a hue picked to match the theme. The y ceiling is `chartMax` (next 1/2/5×10ⁿ), so ticks are round and the axis holds still while the poller feeds points in. templui exposes no tick options: anything finer is set on the live instance through `inst.config.options` — **never `inst.options`**, which is a resolver proxy that recurses until the stack blows.
- **The shell is boosted**: `<body>` carries `hx-boost="true"` + `hx-swap="innerHTML transition:true"`, so every in-shell link and form is an AJAX body swap wrapped in a View Transition (`#page`, the only named element — templui's sidebar inset is a second `<main>`, and two elements sharing a name abort the transition). Three consequences. A link or form that leaves the shell for a page with a `<head>` of its own (`/admin/signin`, logout) sets `hx-boost="false"`, or its layout is spliced into this one. A change to `<html>` — palette, language — cannot ride a body swap: the handler sets the flash itself and answers `hxRefresh`, since htmx follows a 303 without ever seeing its headers. And a form that submits itself from JS uses `requestSubmit()`, never `submit()`, which fires no submit event and so escapes htmx into a full page load. `hx-history="false"` is deliberate: the back button re-fetches rather than let htmx park every rendered page — token secrets included — in `localStorage`. Search, sort and pager links keep their own `hx-swap` and stay instant, without a transition.
- **Hovering a link loads it**: htmx's `preload` extension (vendored beside htmx) fetches a link the pointer has rested on for 100ms, so the click is served from the browser cache. That is what `Cache-Control: private, max-age=5` + `Vary: Cookie` on admin GETs buys (`isAdminPage`, server.go) — five seconds is the hover-to-click window, and since every admin POST answers with a flash cookie, the redirect after an action asks with a different `Cookie` header and can never be served the copy taken before the change. Anything polled rather than navigated asks with `cache: 'no-store'` (the status page). The `preload` attribute sits on the sidebar's content and on `#page`, never on `<body>`: the extension initialises what it finds *under* the node htmx just processed, and a boosted swap replaces the body's children, not the body.
- **A named element travels between pages**: `vtStyle(text)` (helpers.go) derives a `view-transition-name` from the text itself, so a cache row on the dashboard and the title of that cache's page agree without threading an id through both — the row flies into the title instead of both cross-fading. Two rules or it silently stops working: the name must be unique on the page (two elements sharing one abort the transition), and the element must make a single box — a named inline element that can break across lines is skipped, which is why the row's `<a>` is `block`.
- **Flash/PRG**:
 POST handlers respond with `flashRedirect`/`instanceFlash`/`accountFlash` (one-shot cookie + 303, popped by the GET renderers via `popFlash`) so refresh never re-executes an action. Only secret-bearing responses (token create) render directly. htmx fragment endpoints must not render full pages to signed-out users — `requireUser` sends `HX-Redirect` on `HX-Request`.
- `renderInstance` refuses non-admins even though callers gate too — keep that defense in depth.

## Testing notes

- `internal/server/views/smoke_test.go` renders every exported component and asserts English marker strings — catalog values in `i18n.go` must keep matching those markers.
- Server tests assert the PRG contract (303 + flash on landing page), not bare error codes.
- E2E/bench live in `tests/` (`tests/e2e/cli.sh`, `tests/bench/bench.sh`); not part of `go test`.
- **`just check` does not cover the k6 suites.** They pin the wire contract (status codes, request/response fields), so any change to one needs `just k6-conformance` — the trio CI's `ops` job runs — before pushing. Every k6 recipe depends on `k6-image`, because `docker compose run` otherwise reuses a stale server image and the suite silently tests the wrong binary.
